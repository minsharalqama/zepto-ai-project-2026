# Module 1 — Data Pipeline

## What I did in this module

For this module, I used `books.toscrape.com` as the data source. I used Python with `requests` and `BeautifulSoup` to scrape the book details from the website.

I collected the book title, price, star rating, availability, and category. I scraped books from at least 3 categories and collected more than 60 books as required in the project.

After collecting the data, I first saved the raw scraped data in `scraped_books_raw.csv`. I then cleaned the required columns and saved the cleaned data separately in `scraped_books_clean.csv`.

For the price conversion, I used the fixed rate given in the project:

**1 GBP = 105.50 INR**

I used this fixed value for calculating `price_inr` instead of using any live exchange-rate API.

## Files

The main Python file I used for this module is `run_pipeline.py`. It contains the scraping, cleaning, database creation, SQL queries, and pandas validation parts.

The other files generated by the pipeline are:

* `scraped_books_raw.csv` – raw data collected from the website.
* `scraped_books_clean.csv` – cleaned data after processing the required fields.
* `books.db` – SQLite database containing the `categories` and `books` tables.
* `queries_output.md` – SQL queries with their outputs and the pandas comparison results.

```bash
pip install -r data_pipeline/requirements.txt
```

After that, I ran the main script:

```bash
python data_pipeline/run_pipeline.py
```

The script performs the complete process automatically. It finds the categories, scrapes the books, cleans the data, creates the SQLite database, runs the SQL queries, and generates the required output files.

## Data cleaning

For the price column, the website gives the price along with the GBP symbol. I removed the symbol and converted the value into a numeric `price_gbp` column.

The star rating was available as text such as `One`, `Two`, `Three`, `Four`, and `Five`. I converted these values into numbers from 1 to 5 and stored them in the `rating` column.

For availability, I checked the text and converted it into an `in_stock` boolean value. `In stock` is treated as `True` and `Out of stock` is treated as `False`.

If an unexpected availability value is found, I drop that row instead of assuming its value.

For numeric values, if there is an invalid price or rating that cannot be converted properly, I use the median value for that column. I also print these cases in the terminal so that I can see when the cleaning logic has been used.

## Price conversion

After cleaning the GBP price, I calculated the INR price using the fixed conversion rate from the project.

```text
price_inr = price_gbp * 105.50
```

For example, if a book costs `10.00 GBP`, the INR value is calculated as:

```text
10.00 * 105.50 = 1055.00 INR
```

I used the fixed project rate directly and did not make any external currency API call.

## SQLite database

After cleaning the data, I stored it in a SQLite database named `books.db`.

I created two tables:

```text
categories
- category_id
- category_name
```

and

```text
books
- book_id
- title
- price_gbp
- price_inr
- rating
- in_stock
- category_id
```

The `category_id` in the `books` table is used as the foreign key to connect each book with its category in the `categories` table.

I kept the categories in a separate table instead of repeating the category name for every book. This gives the database the required primary-key and foreign-key relationship.

## SQL queries

After inserting the cleaned data into SQLite, I ran the required SQL queries to check and retrieve information from the database.

I included queries using:

`SELECT`, `WHERE`, `ORDER BY`, `LIMIT`, `DISTINCT`, `BETWEEN`, and `JOIN`.

I saved the queries and their outputs in `queries_output.md`.

For the JOIN query, I joined the `books` and `categories` tables so that the book information could be viewed together with its category.

## Pandas comparison

I also checked the SQL result using pandas.

First, I loaded the SQL query result using `pd.read_sql()`.

Then I used the DataFrames already available in memory and recreated the same JOIN using `pd.merge()` without using SQL.

Finally, I compared both results to check whether they were equivalent.

This helped me verify that the JOIN result obtained from SQLite was the same as the result produced using pandas.

## Final result

After running the script, the raw book data is scraped and saved, the required fields are cleaned, the GBP prices are converted into INR, and the data is stored in the normalized SQLite database.

The SQL queries are then executed and their results are saved. The final pandas comparison also confirms that the SQL JOIN and pandas merge produce the same result.
